## 三、改变选题顺序：先找到能研究的真实任务，再提方法

之前的调研更偏向于：

阅读论文 → 发现理论缺口 → 提出方法 → 寻找实验平台 → 发现无法验证或竞争太强 → 否定。

本轮请优先采用相反的路径：

**确认可用的任务与实验资产 → 找到具体、可重复的行动失败 → 分析失败机制 → 对照最强简单基线与现有方法 → 提出必要且有区别的新机制 → 确定选题。**

请先筛选 2—4 个足够具体的实验组合，每个组合必须尽可能明确：

- 机器人任务及其动作接口；
- 现成策略、模型或控制方法；
- 官方代码仓库；
- checkpoint、训练数据或演示数据的实际可获得性；
- 仿真器、评价脚本、成功率定义；
- 已有任务成功率及其证据来源；
- 是否可以在单卡 3090 上运行或做轻量方法改进；
- 是否需要从头训练大型模型；
- 已知的环境配置和复现障碍；
- 可以观察、记录和控制哪些空间变量、动作变量与失败结果。

**逐项核查官方仓库、README、配置文件、权重链接、数据说明、许可证和评价代码。**

请严格区分：

- 论文作者报告成功；
- 官方代码或权重确实存在；
- 第三方曾经成功复现；
- 我们的本地环境已经实际跑通。

本轮没有运行实验，因此绝对不能把前三者写成第四者。

优先选择已经有明确正成功率证据、能够观测具体动作、可以进行可控扰动与统计评估的平台。不要为了一个看起来高级的科学问题，强行选用尚无可靠基线的复杂系统。

可以适度考虑之前没有充分探索的任务，例如接触丰富的操作、铰接物体、移动操作或其他具身任务，但它们只是备选场景，不是预设研究方向。

## 四、必须从具体行动失败中寻找科学问题

我不想再看到只停留在“空间信息很重要”“现有模型缺乏鲁棒性”“空间推理与动作之间存在鸿沟”这种宽泛表述。

对于每个候选实验组合，请寻找具体的行动失败证据。例如机器人到底在哪一步失败、失败是否可重复、是否真的与空间信息有关、现有方法为什么不能轻易修复。

你需要区分：

- 空间感知或几何估计本身出错；
- 策略没有正确利用已有空间信息；
- 动作表示或接口造成信息损失；
- 闭环控制、接触动力学或执行误差；
- 数据分布、仿真器或评测协议引入的假象。

不能把所有行动失败都归因于“空间理解不足”。

优先寻找来自论文实验、失败案例、消融、附录、开源 issue、复现记录等至少两类相互独立的证据。若无法获得独立证据，请明确说明。

对每个核心失败，回答：

1. 失败的直接表现是什么？
2. 目前证据支持什么原因？哪些原因只是推测？
3. 如果使用一个足够简单的现有方法，是否就能解决？
4. 什么观察结果会推翻我们对失败机制的解释？
5. 为什么这个问题值得研究，而不只是某个开源项目的工程 bug？

## 五、提出候选，但必须主动收敛

在确认实验资产和失败证据后，提出 **2—3 个真正不同的科学问题或方法假设**，而不是同一方向的三个包装版本。

每个候选必须包括：

**科学问题：** 用一句可证伪的话说明究竟想研究什么。

**核心假设：** 预测什么条件下会发生什么行动改善或失败变化。

**方法机制：** 具体改变策略的信息处理、动作决策或控制过程中的哪一个环节，为什么这可能解决目标失败。

**最近邻竞争：** 至少对照三项最接近的已有工作，说明它们已经解决什么、尚未验证什么，以及我们与它们的实质差异。

**强简单基线：** 包括合理的经典方法、轻量修正、数据增强、简单反馈控制、现有开源方法等。不能只挑弱基线衬托新方法。

**最可能的否定结果：** 例如一个简单基线就达到同样效果、目标失败其实不由空间因素主导、基线成功率不足、方法改善只来自额外参数或计算量。

**资源成本：** 在 3090 上需要的显存、训练或推理开销，以及当前能确认和不能确认的部分。

不要把“增加一个模块”“换一种门控信号”“重新加权损失”“更换数据集”“组合已有方法”直接称为创新。

如果方法本质上只是工程整合，请直接指出，并寻找是否存在真正值得验证的新机制。

但同样不要因为某个模块曾经被使用，就推断所有相关组合都失去创新空间。关键是**科学问题、作用机制、适用条件和实验证据**是否真正不同。

## 十、最终报告格式与强制交付
