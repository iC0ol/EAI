# 盲测与泄漏审计

结论：正式盲预测接口通过检查。冻结之后才执行一次独立真值评分；不存在利用 NaN 边缘、可识别偏移文件名或跨污染版本比对的估计路径。

| 程序角色 | 可读实验数据 | 不可见数据 |
|---|---|---|
| Builder | 官方源文件、原 split 和注入计划 | 不作为估计器 |
| Fitter | 八个干净锚点视图、无注入信息的设置 | 原 HDF5、所有查询、真值 |
| Estimator（每包独立进程） | 一个有限匿名包、冻结模型 | 原 HDF5、注入 manifest、私有 Oracle、其他查询、builder/scorer |
| Scorer | 已冻结预测及哈希，验证后才读真值/Oracle | 不向估计器回传标签 |

隔离为实际 bubblewrap 0.6.1 的 mount/PID/network namespace，非仅靠代码约定。只读挂载 Python/标准库/项目 venv 和白名单代码；不挂载 GPU 设备。真实原 HDF5 以及生成后已经存在的私有真值路径，均在主动读取探测中返回 FileNotFoundError。结果见 `anchor_access_probe.json` 与 `query_access_probe.json`。

两端统一裁四步，不先暴露含 NaN 的原污染数组；112 包所有数值有限、NaN 数全零。每来源七包 N=T−8 一致，观测逐值相同；七种注入的长度分布完全相同。不同源保留自然长度，未为对齐丢弃动作转换段。长度/NAN 计数都是无偏移信息的线索。

所有候选 −4…4、H≤4、phase≤4 使用 `[8:N−4)` 相同评分时刻，索引审计全部通过。估计器 schema 拒绝注入字段、额外元数据和非有限数；随机文件重命名/执行次序测试不改变数值预测。每包独立进程也阻断利用同源七包相互比较的捷径。

匿名 d=0 条件的 command 自然等于干净动作，但没有 d=0 标签或特权 clean-action 参考。它与其他条件一样单包运行；禁止的对象是额外原始 clean actions/Oracle 文件，而不是去掉协议要求的零注入对照。
