## 07 结论撤回与改写

1. **P2“完全没做几何验收”——撤回。** `results/semantics/camera_raymap_checks.json` 已有单位方向/矩/正交误差约 1e-7、四个解析像素 ray/反投影、OpenGL 与 crop 约定记录；`validate_semantics.py:38-48` 也执行了这些断言。应改为：**已有解析自一致验收，但缺少独立 MuJoCo 渲染/实际像素对应真值**。因为该检查用同一解析 ray 加 origin，再用同一 R/K 投回，属于代数闭环；不能据此宣布 P2 已排除，也不能说未做。

2. **P1“1–2 mm cube size 是已确认主因”——撤回因果排序。** 无逐 demo XML、共享一个 env 状态恢复是**上游 Dataset 原路径**，不是本轮新增差异；10/10 专家回放显著降低了动力学/动作接错疑虑。仍属未排除的实施差异，但不能当已证实主因。

3. **“训练未学会”——改写。** 0/32 发生在新 test camera pool；没有同 checkpoint、训练 camera 条件下的部署对照，不能区分“训练未形成策略”与“训练相机→测试相机泛化失败”。准确表述是：**所需 baseline 验收未通过**。

4. **“整段 z 位移 −0.084 m”——撤回。** 那是目标平移增量之和，不是实测 EEF 位移；首动作跨 root 标准差 X≈6.9e-5、Y≈2.6e-5、Z≈1.2e-4 m，不能笼统写“约 1e-5”。

5. **4/32——改写。** 它只是最低工程排除地板，不是论文复现质量线，也不足以支持机制研究。恢复研究资格需要**可信 clean 能力 + 对复现差距的解释**。

6. **“persistent/IID 无 20pp 差且区间宽 → 停止/阴性”——改写。** 若真出现，只能记 **INCONCLUSIVE**；可因机会成本停止，但不是 VALID-NEGATIVE，也不自动授权两周重训。

## 仍不同意的点

- **P2 不能因解析检查通过就完全排除。** 仍需一次独立渲染对应检查（已知 3D 点→MuJoCo 像素→ray），否则相机/raymap 约定错误仍是未排除项。
- **0/32 不能归因于标定误差，也不能归因于“训练失败”。** 缺的是同 checkpoint、训练相机 pool 的 clean 对照；这是实施恢复条件，不是科学结论。
- **per-demo XML 是上游限制，不等于可以忽略。** 它仍可能影响训练图像与动作一致性；只是不能未经核查就列为主因。
- **MoVie 已覆盖冻结动力学 + 测试时视觉适应；** 相机隐变量/边缘化只是条件性设想。没有可信 baseline、明确缺陷、且 simple pose-jitter/校准闭合失败之前，不能谈新机制。

## 最终投入决定

**停止 F 实验，不新增训练、推理、rollout 或源文件修改；当前无优先论文候选，正式 persistent/IID、moved-stale、350 rollouts 全部 NOT_RUN。**

只保留一条**只读恢复路径**，且不自动执行：
1. 取得可信官方行为参照（官方 checkpoint，或同 checkpoint 训练 camera 部署对照）；
2. 补一次独立渲染 ray 对应检查；
3. 核对数据/依赖版本与训练入口差异；
4. 只有定位到**单个具体原因**后，才单独预登记一次有界修复与预算；否则封存 F。

即使修复后 clean 通过，F 也只是**问题验证**，不是论文资格；必须先过 simple pose-jitter/校准强基线，并解释相对 KYC/CamVLA/AnyCamVLA/MoVie 的剩余差异。**不把复现或修 bug 包装成贡献。**
